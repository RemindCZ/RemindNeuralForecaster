Local CUDA research environment

From closed MT5 bars to a live neural forecast.

This manual covers the complete REMIND Neural Forecaster 0.8.1 workflow: local installation, MetaTrader 5 data synchronization, leakage-safe datasets, CUDA training, untouched-test evaluation, explicit model activation and live High/Low/Midpoint forecast overlays.

C++20 / CUDALSTM · GRU · RNN127.0.0.1 onlyClosed bars onlyNo automated trading
Research software, not investment advice. Forecasts can be wrong. The application and EA do not guarantee performance or profit. EA_Forecaster does not open, modify or close trades.

1 · Introduction

What the application does

REMIND Neural Forecaster is a local Windows research application. The browser is the control surface; native C++ and CUDA perform the numerical work.

Data

MT5 Dataset Store

EA_Forecaster sends authenticated batches of closed OHLCV bars. The server deduplicates bars, records corrections and persists each broker/symbol/timeframe stream independently.

Research

Reproducible experiments

Immutable snapshots contain causal features, chronological Train/Validation/Test splits and Train-only scalers. Best validation checkpoints receive one untouched-test evaluation.

Deployment

Explicit live inference

An eligible checkpoint must be registered and activated deliberately. New closed bars trigger asynchronous inference; the EA displays the resulting range without trading.

3 · Build and launch

Start the Windows application

Build the CUDA Release configuration

cmake -S . -B build -A x64
cmake --build build --config Release
.\build\Release\RemindNeuralForecaster.exe

The executable opens the local UI automatically. Add --no-browser for service-style operation or automated checks. Press Ctrl+C in its console to stop it cleanly.

Useful launch options

OptionPurpose
--no-browserRun without opening the default browser.
--data-dir PATHUse a different persistent data directory. Environment equivalent: REMIND_DATA_DIR.
--mt5-token TOKENSupply the MT5 installation token. Environment equivalent: REMIND_MT5_TOKEN.
--log-level LEVELSelect error, warn, info, debug or trace. Environment equivalent: REMIND_LOG_LEVEL.

Verify the running version

(Invoke-RestMethod http://127.0.0.1:7470/api/v1/health).version

For this manual, the expected version is 0.8.1. If the UI or EA expects a newer protocol, stop the old process, rebuild the canonical Release executable and start it again.

4 · MT5 bridge

Install EA_Forecaster

  1. Open the MT5 data folder. In MetaTrader choose File → Open Data Folder, then open MQL5\Experts.
  2. Copy the bridge. Create an Experts\Forecaster folder. Copy mt5\EA_Forecaster.mq5 into it and copy the repository's mt5\include directory beside it.
  3. Compile the installed source. Open that exact EA_Forecaster.mq5 in MetaEditor and press F7. Require 0 errors and 0 warnings. Recompile whenever an included .mqh changes; copying an include does not rebuild the existing .ex5.
  4. Allow the loopback URL. In MT5 open Tools → Options → Expert Advisors, enable Allow WebRequest for listed URL, and add exactly http://127.0.0.1:7470.
  5. Obtain the token. If no token was supplied at launch, Forecaster creates %LOCALAPPDATA%\RemindNeuralForecaster\installation.token. Copy its value into InpInstallationToken. Never place it in a URL, screenshot or log.
  6. Attach the EA. Open the required symbol/timeframe chart, drag EA_Forecaster onto it, review the inputs and enable it. One chart represents one complete stream identity.

Important EA inputs

InpForecasterUrlLocal service URLKeep the default loopback URL.
InpInstallationTokenSeparate MT5 API credentialRequired; never disclose it.
InpInstanceNameStable non-account instance nameUse a distinct value when intentionally running multiple EA instances for the same chart identity.
InpBackfillBarsMaximum historical barsLarge backfills take longer and require more storage.

Strategy Tester limitation: MT5 WebRequest is unavailable in Strategy Tester. Compile-time and golden-protocol tests can run there, but final transport validation requires a live or demo terminal chart.

6 · Data

Streams and immutable snapshots

Streams are isolated by broker server, original broker symbol, timeframe, timeframe seconds, price digits, point size and schema version.

Data synchronization

  • The EA sends only closed bars and performs network work only from OnTimer.
  • Identical bars are duplicates and do not change the dataset revision.
  • Changed content at an existing timestamp is recorded as an audited correction.
  • Broker-server timestamps are preserved; the current UTC offset is used only to confirm that bars are closed.
  • Gaps and DST discontinuities begin new causal segments; the pipeline does not invent missing bars.

Create a snapshot

  1. Open Data and select a connected stream.
  2. Choose the range, input window W, forecast horizon H, and Train/Validation/Test percentages.
  3. Create the snapshot and wait for completion. The service writes an immutable checksummed .rnfs artifact.
  4. Confirm the stream identity, revision, split counts, feature schema and fingerprint in the preview.
Leakage control: splits remain chronological and are never shuffled. Inputs and complete target horizons must stay inside their split. Feature and target scalers are fitted from Train only.

FeatureSchema v1

The fixed feature row contains 1- and 3-bar log returns, High/Low log range, candle body, upper and lower wick, close position, log tick volume, tick-volume change, relative spread, and 5- and 20-bar volatility. Targets are future High and Low log returns relative to the base close for every T+1 … T+N.

7 · Training

Configure and run a CUDA experiment

Each experiment uses one immutable snapshot and produces persistent metadata, loss history, a best checkpoint and—when eligible—an OOS report.

Configuration reference

FieldPurposePractical guidance
LayerLSTM, GRU or RNN recurrent cellCompare architectures as separate experiments; do not select by Train loss alone.
Layers / Hidden sizeModel capacityLarger values consume more VRAM and may overfit.
BatchSamples per optimizer stepUse Estimate VRAM before starting.
EpochsMaximum training durationEarly stopping may finish sooner.
Learning rateAdamW update sizeUse decimal point or comma; the client normalizes both safely.
AdamW decayDecoupled weight decayTune as a research parameter, not a universal default.
DropoutDeterministic training regularizationApplied during training, not live inference.
Gradient clipGlobal gradient boundHelps contain unstable recurrent updates.
SeedReproducibility seedKeep identical when comparing one configuration change.
Early-stop patienceEpochs without validation improvementThe best checkpoint is retained even when later epochs worsen.

Training lifecycle

queued → preparing → training → evaluating ends as completed or early_stopped. User cancellation passes through cancelling to cancelled. A process restart marks unfinished work interrupted; numerical, evaluation or persistence errors become failed.

During training, weights, gradients, dropout state and AdamW moments remain on the GPU. HTTP, WebSocket and browser rendering stay independent from the CUDA worker.

8 · Research

Read the untouched-test report

After training, the best validation checkpoint is evaluated once on the Test split. Test data never selects the checkpoint or controls early stopping.

MAE

Average absolute price error. Lower is better and easy to interpret in price units.

RMSE

Root mean squared error. It penalizes larger misses more heavily than MAE.

Directional accuracy

Share of cases where the predicted midpoint direction agrees with the realized direction.

Range overlap

Intersection-over-union between predicted and realized High/Low ranges.

Skill vs. persistence

1 − model error / baseline error. Positive values beat the configured persistence baseline; negative values do not.

Cases and crossings

Cases report sample count. Crossings show how often raw High/Low outputs required deterministic ordering.

How to review an experiment

  1. Confirm that training completed or early-stopped normally and note the best validation epoch.
  2. Inspect Train and Validation loss together. A falling Train loss with worsening Validation loss indicates overfitting.
  3. Review aggregate KPI values, then inspect every forecast horizon. A strong T+1 result does not imply a strong T+N result.
  4. Compare against persistence and another experiment created from the same stream and compatible evaluation context.
  5. Register a model only when its behavior, limitations and intended stream are understood.
Do not cherry-pick the Test split. Repeatedly changing hyperparameters in response to Test results turns Test into another validation set. Preserve a genuinely unseen period for final decisions.

9 · Models

Register and activate deliberately

  1. Select an eligible experiment. It must have a valid best checkpoint, compatible snapshot v2 context and OOS report.
  2. Register the candidate. Registration records immutable links and hashes; it does not activate the model.
  3. Inspect compatibility. Verify broker, symbol, timeframe, architecture, horizon, schema and OOS metrics.
  4. Activate explicitly. Forecaster validates hashes, loads immutable weights and workspace into VRAM, performs smoke inference and only then swaps the active model.
  5. Confirm the exact stream. One active model is allowed per complete StreamIdentity. A model for H4 cannot serve an M5 chart.

Activation is transactional. If validation, allocation or smoke inference fails, the previous active model remains available. Deactivation stops new inference and makes any prior forecast ineligible for live display.

10 · Live forecast

Understand the chart overlay

A changed closed bar creates one revision-bound forecast. The EA receives it through the existing authenticated heartbeat only when its forecast ID changes.

High

Upper path

Predicted High for each future horizon.

Midpoint

Central path

Midpoint between the ordered predicted High and Low.

Low

Lower path

Predicted Low for each future horizon.

Freshness rules

  • Waiting for model: no compatible active model exists for this exact stream.
  • Waiting for forecast: a model is active, but no current inference result is available yet.
  • Forecast live: model, stream, dataset revision, latest closed bar and freshness checks all match.
  • Forecast stale: the result no longer matches current data or age limits. The EA removes it instead of presenting it as current.

Forecast identity binds the stream, model hash, dataset revision and base-bar time. Duplicate heartbeats do not redraw the chart. Corrections or model changes invalidate the old overlay and cause safe cleanup.

12 · Storage and security

Local data ownership

The default persistent root is %LOCALAPPDATA%\RemindNeuralForecaster. A custom location may be supplied with --data-dir. Dataset streams, snapshots, experiments, checkpoints, OOS reports, model-registry metadata and bounded forecast history are checksummed and written using crash-safe or atomic replacement strategies.

Browser boundary

The UI and API share the loopback origin. State-changing browser calls and WebSocket upgrades use a per-process, HttpOnly, same-site session cookie with Origin validation.

MT5 boundary

MT5 uses a separate installation token in request headers plus a connected instance identity. It cannot substitute the browser cookie.

Backup

  1. Stop Forecaster cleanly so no write is in progress.
  2. Copy the complete data directory to the backup destination. Preserve the hierarchy and token securely.
  3. Restore only to a compatible application version and validate artifacts through the application before activation.
Secrets: never publish installation.token, browser cookies, private model files or raw trading datasets. Screenshots intended for publication should be checked for account numbers and broker-specific information.

13 · Operations

Routine operation and updates

Normal startup order

  1. Start the current canonical Release executable.
  2. Verify CUDA and version in Overview.
  3. Start MT5 and attach the compiled EA.
  4. Wait for EA status live.
  5. Confirm the active model and forecast freshness.

Normal shutdown

Stop Forecaster with Ctrl+C. MT5 may remain open; the EA transitions to offline/backoff and removes stale live objects. Removing the EA cleans up only objects carrying its own instance/stream prefix.

Updating the application

  1. Back up the data directory.
  2. Stop the running Forecaster process before replacing the Windows executable.
  3. Build or install the new version and verify /api/v1/health.
  4. If EA or any .mqh changed, copy the complete matching source set and recompile the installed EA_Forecaster.mq5.
  5. Reattach the EA if MT5 did not reload the new .ex5.

Logging

Use info for normal operation. Enable debug temporarily for queue, memory, feature preparation and latency diagnostics. Logs intentionally exclude tokens, browser cookies, request bodies, raw bars, full tensors, model weights and storage paths.

15 · Limitations

Use the result as evidence, not certainty

  • Forecasts are statistical estimates and can fail under changing market regimes.
  • The current engine uses FP32 neural computation with carefully validated CPU/CUDA parity; numerical reproducibility does not imply market predictability.
  • MT5 WebRequest is synchronous, so the EA limits work to one bounded request per timer event and performs no network work in OnTick.
  • Broker timestamps are not normalized across independent feeds. Do not merge streams casually.
  • One current CUDA pass may complete before cancellation is acknowledged.
  • A live forecast is informational. Any future trading automation requires a separate, explicit risk and execution design.
Recommended practice: preserve experiment provenance, compare against simple baselines, review every horizon, keep a truly unseen evaluation period and validate behavior on a demo account before relying on any workflow operationally.
